# Walkaway monorepo — wrapper scaffold

This repository structure is the demo wrapper only. Component implementation
has **not** been migrated into this tree yet. Each component README names the
canonical working source, the component boundary, and the files that belong in
the wrapper when the selected demo requires migration.

## Layout

- `apps/hermes-browser/` — native supervised local browser surface.
- `apps/android-notification-bridge/` — Android app scaffold generated by
  Android CLI. Android is the notification pathway toward the glasses.
- `apps/glasses-web/` — 600x600 glasses web surface, modeled on Meta's
  sample applications and designed for sequential focus input.
- `apps/phone-approval-web/` — phone-sized approval/status surface.
- `apps/desktop-supervision/` — desktop host/supervision surface boundary.
- `services/muse-connector/` — Muse MCP connector service boundary.
- `services/hermes-host/` — trusted host-channel bridge for Hermes decisions.
- `services/agent-driver/` — agent-channel driver boundary.
- `services/walkaway-relay/` — existing Chrome companion relay boundary.
- `services/demo-fixtures/` — real local services used by the chosen demo.
- `packages/protocol/` — shared cross-surface contracts.
- `packages/design-system-glasses/` — shared 600x600 design rules/tokens.
- `packages/audit/` — shared audit/receipt schema boundary.
- `tests/e2e/` — real-system demo acceptance tests; no mocked browser,
  relay, or approval surface.
- `submission/` — hackathon/connector submission assets boundary.

## Wrapper rule

Do not copy code into a wrapper folder until the selected three-minute demo
requires that exact code path. A folder README is a boundary contract, not a
claim that the component is implemented inside this repository.
